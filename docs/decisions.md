## 2026-10-08 — Test harness: mock routing by prompt markers, lint scoped to new files

- Context: New `MockProvider` must serve concurrent agents deterministically; `ruff check src tests` reports 277 pre-existing violations (UP/I001/BLE001) across untouched `src/` files.
- Decision: (1) Mock scripts selected by matching role markers in request text (planner/synthesizer/critic/researcher/solver), with `fail_next`/`always_fail` fault injection and `from_fixture` JSON loading. (2) `make lint` gates only `src/providers/mock_provider.py` + `tests/`; full-`src/` ruff cleanup is a separate task. (3) Autouse socket guard blocks non-loopback `connect` (Windows asyncio needs 127.0.0.1 socketpair; respx intercepts HTTP without sockets).
- Consequences: `pytest` provably makes zero external network calls; pre-existing lint debt stays visible and untouched.

## 2026-10-08 — Smoke run: live-verified model IDs, 120 s Gemini bound

- Context: First real-key run failed 100% of calls — every hard-coded model ID was retired (Gemini 2.x, Groq Llama-*, old OpenRouter slugs). Gemini 2.5-flash is also gated for new API keys; only 3.x works there.
- Decision: Refresh IDs from live provider catalogs (`scripts/list_models.py`, names-only output): Gemini → `gemini-3.8-flash`, Groq → `openai/gpt-oss-20b` / `openai/gpt-oss-120b`, Cerebras → `gpt-oss-120b` / `qwen-3.8-27b`, OpenRouter free → `google/gemma-4-26b-a4b-it:free` (+ nemotron/inkling fallbacks). Bound the legacy Gemini SDK call with `asyncio.wait_for(120 s)` since it can hang indefinitely and the SDK offers no timeout.
- Consequences: Complete 3-min runs work (6 calls, ~5k tokens, <11 s when Gemini cooperates). Long-term fix is still `models.yaml` + per-call timeouts everywhere (audit #1); Groq no longer serves any Llama model, which weakens the family-diversity story until the router is family-aware.

## 2026-10-08 — Provider layer is config-driven (models.yaml + registry)

- Context: Every model id lived in 3+ places (router tables, provider lists, settings defaults); all rotted simultaneously. Four `openai`-SDK provider modules duplicated the same 60 lines.
- Decision: (1) `models.yaml` is the single catalog (TECH_STACK 3.5 schema + `enabled`/`headers`/`timeout_seconds`; limits/context are null placeholders with dashboard pointers). (2) One `OpenAICompatibleProvider` (httpx) for Groq/Cerebras/OpenRouter/Mistral/NVIDIA; retry only 429 (+Retry-After, capped)/502-504/timeouts/connect errors, never 401/403/400/malformed. (3) `get_provider(provider_id, api_key)` registry; Gemini kept native but raises the same `RateLimited/AuthError/ProviderDown/BadResponse` via shared `classify_exception`. (4) HuggingFace `enabled: false` (registry refuses it); dead `ExperientialProvider` + per-provider modules deleted; `openai`+`groq` SDK deps removed (verified zero imports). (5) `Settings.*_default_model` fields removed — defaults come from yaml. (6) `make lint` now gates `src/providers tests scripts` (also micro-cleaned `base.py` annotations).
- Consequences: Switching a model id = editing models.yaml only (proven by test + grep: only the family-vocabulary enum remains in code). Router resolves (provider, model, family) from catalog order. Pre-existing violations outside providers/tests/scripts remain untouched.

## 2026-10-08 — BYOK key handling (TECH_STACK s5): stores, SecretStr, endpoints

- Context: Keys lived as plain strings from settings `.env` only; no per-request path, no key test, no status view, no mode switch.
- Decision: (1) `src/core/keystore.py` with `RequestKeyStore` (web, per-run memory, wiped in orchestrator success+failure paths), `KeyringKeyStore` (desktop, lazy `keyring` import, catalog enumeration), `EnvKeyStore` (dev, refuses to construct when `app_env=production`); `get_keystore()` on new `APP_MODE=dev|web|desktop` (Literal-validated). (2) All key fields are `SecretStr`; added `reveal()` used only at provider/SDK/JWT call sites (fixed a real bug found en route: f-string of a SecretStr sends literal `**********` as the bearer token). (3) `provider_keys` request field flows to `Orchestrator.execute(provider_keys=...)` via an isolated `ModelRouter(keys=...)`; never mapped onto the `Execution` record. (4) `POST /api/keys/test` (SecretStr body, tiny call, `{valid, rate_limited, error_code}`, 404 on unknown provider) and `GET /api/providers/status` (names/families + rough 0.7-margin capacity from yaml limits) in new `src/api/keys.py`, registered in `main.py`. Removed `Settings.*_default_model` leftovers already gone; added `keyring` dep (Windows needs pywin32 alongside).
- Consequences: `make lint` gate extended to owned files (`src/providers`, keystore/config/keys, tests, scripts); pre-existing B008/BLE001/S110 in auth/conversations/executions/orchestrator left untouched. Live smoke after the refactor hit Gemini 429 quota-exhausted and failed cleanly — confirming free-tier 429 handling (cooldown/retry) is the next must-fix, already audit #5.

## 2026-10-08 — Logging hardening: masking filter + generic client errors

- Context: No masking filter existed; orchestrator WS error events and failed answers echoed raw exception text to clients; FastAPI's default 422 echoes offending input (including submitted keys).
- Decision: (1) `KeyMaskingFilter` in `logging_config.py`: headers first, then inline dict/list field values, then scalar fields, then provider prefixes, then 40+ opaque tokens; attached to the assembly logger, root, and named HTTP/SDK loggers (filters only apply at the record's origin logger — root alone does not cover httpx records). (2) Orchestrator error event + failed answer are now fixed generic strings; full error stays server-side. (3) Custom 422 handler logs only `{type, loc, msg}` shapes and replies `{"detail": "Invalid request."}`. (4) Canary `SECRET_CANARY_12345` in `tests/test_log_canary.py` (12 tests) covering logs, SQLite file bytes, responses, WS-shaped events, and exception text.
- Consequences: Logger filters cannot rewrite traceback bodies (frame locals aren't printed by default, so this is accepted); `ruff format` intentionally not applied to legacy `main.py`/`orchestrator.py` (100-line noise — check-only gate for those); the 3-fake-key API variant is flaky under TestClient (per-request portals vs background tasks), so the hermetic canary uses one key while on_progress captures cover event shapes.

- Context: Router counted providers, not families — Groq+Cerebras both serving gpt-oss looked like diversity; no critic-family rule, no failover, no routing provenance.
- Decision: (1) `route_team()` assigns solvers first on fresh families, critic off solver families, rest spread-then-reuse; 2 families → warning, 1 → degraded flag; quota-unaffordable providers filtered (fail-open). (2) `RoutingDecision(provider, model, family, role, reason)` replaces ModelAssignment (alias kept); logged per agent and carried into `agent_info`, `ExecutionResult.routing/degraded/warnings`, and new `AgentRun` rows via `_persist_agent_runs`. (3) `fallback_for()`: different family → same family/other provider → None; `AgentManager` retries once on RateLimited/QuotaExhausted/ProviderDown with stable agent ids (debate keeps stale-carryforward). (4) `create_team` keeps its signature; duck-typed routers get a legacy rotation path.
- Consequences: Family/reason DB columns deferred (create_all can't migrate SQLite; names-only rows for now). Debate-round retry is future work. Groq+Cerebras sharing gpt-oss is now correctly counted as one family.

## 2026-10-08 — Quota limiter: windows, cooldowns, day persistence, router skip

- Context: Free-tier 429s killed runs with no recovery (seen live: Gemini quota-exhausted); no rpm/rpd tracking, no cooldowns, no capacity data anywhere.
- Decision: (1) `src/providers/quota.py`: sliding-minute RPM/TPM windows, UTC-day RPD counters in new `quota_usage` table keyed by salted SHA-256 fingerprint (never the key), `acquire()` returning a `QuotaLease` (async CM) that waits boundedly on full windows but raises `QuotaExhausted` on cooldown/spent days, `report_429` cooldowns, per-provider semaphore caps, UTC day strings so desktop/hosted agree. (2) `generate()` acquires a lease and reports 429s into the shared singleton; router filters exhausted keys (fail-open) and exposes `capacity_estimate()`; planner attaches it read-only to `PlanResult`; status endpoint reports live `remaining()` per available key. (3) Tests use tmp catalogs + in-memory DB; provider-layer tests reset the singleton per test (generate() now writes cooldown state).
- Consequences: With all repo limits still null, the limiter is pass-through except the concurrency cap — fill `models.yaml` limits from dashboards to activate it. Full capacity-aware team sizing (WORKFLOW §4) stays future work; planner only reads/logs today.

## 2026-10-08 — Capacity planner (WORKFLOW §4): pure function + preflight

- Context: Quota math existed (limiter + `capacity_estimate`) but nothing turned it into a team-size verdict; users could launch tiers their keys cannot afford. The endpoint also needed a no-execution way to preview feasibility.
- Decision: (1) New `src/orchestration/capacity.py` — pure functions only (`KeyBudget` counts in, `TeamPlan` out; never raw keys): `affordable_calls` (per-key min(rpm×minutes, rpd) × 0.7, None when all limits unknown, 0 when no keys), `cost_of_plan` (agents + rounds×agents + searches + planner + synthesis), `synth_reserve_seconds` (max(25s, 12%)), `can_start_round`, `heuristic_suggestion` (keyword/length, no LLM), and `plan_capacity` (requested tier standard first, else largest smaller tier standard, else trimmed 3-min minimum, else infeasible with a plain-language explanation). (2) `ModelRouter.quota_snapshot()` — read-only per-key counts (no fingerprints/keys leave). (3) `GET /api/executions/preflight` (JWT-authed, above `/{execution_id}` so the route isn't swallowed; heuristic-only so it spends no quota; names/counts only, never keys in URLs). (4) `tests/test_capacity.py` (25 tests: formula units, every tier vs WORKFLOW call bands, many/few keys, exhausted quota, preflight incl. auth/tier validation).
- Consequences: Time estimates are constants pending first-benchmark measurement (WORKFLOW §4 note). `Orchestrator.execute` does not yet gate on the verdict (Phase 0 CAPACITY_CHECK wiring is the follow-up); preflight is advisory until then. `make lint` gate extended to `capacity.py`.

## 2026-10-08 — Validated planner output (WORKFLOW §3) with retry + heuristic fallback

- Context: The planner emitted an unvalidated dict with a legacy `team` shape (missing `suggested_roles`/`estimated_rounds` per the audit), crashed the run on bad JSON only via a blind default, and never consulted capacity before proposing a team.
- Decision: (1) New `PlanSchema` (Pydantic, `extra="ignore"`): problem_type normalized to the known set, complexity literal, needs_research/needs_code_execution bools, suggested_roles (solver/researcher/critic, non-empty), estimated_rounds 1–8; `PlanResult` keeps its orchestrator-facing fields (`team_composition` now derived from validated roles) and gains suggested_roles/estimated_rounds/needs_code_execution/fallback_used. (2) Chain: cheapest-fast model (`route_for_planning` = first catalog planner model, max_tokens cut 1024→512) → hardened `_extract_json` + schema validation → exactly one retry with the error message, preferring `router.fallback_for` (different family) when available → heuristic fallback (capacity `heuristic_suggestion` + keyword problem-type sniff), so `plan()` never raises. (3) Roles clipped to capacity tier ceilings always, plus a quota-aware trim via `plan_capacity` when the router exposes `quota_snapshot` (fail-open); legacy `team` shape still translated for old prompts/mocks. (4) `tests/test_planner.py` (19 tests: valid/prose-wrapped/legacy/normalized, malformed→retry, persistent-malformed/empty/invalid/empty-roles→fallback with exact call counts, transport-error→direct fallback, fallback-model retry, routing failure, tier + quota caps, heuristic types, key-leak scan).
- Consequences: Mock default plan script (legacy shape) keeps working through translation, so e2e/quota tests pass unchanged. Unknown problem types normalize to `general`; unknown role names are dropped from legacy teams but fail validation in the new shape (retry, then fallback) — strictness is safe because fallback always succeeds.

## 2026-10-08 — Strict AgentOutput contract with retry + family fallback

- Context: Agents returned an unvalidated dataclass (free-form evidence strings, unbounded confidence, silent text fallback on bad JSON), so malformed model output silently poisoned consensus; provenance (provider/model/family/tokens/latency) was scattered or missing.
- Decision: (1) `AgentOutput` is now a strict Pydantic model (`extra="forbid"`): position, reasoning_summary (truncated at 2000 chars, never a CoT dump), confidence 0..1, evidence as `[{claim, source_id}]`, supports/disagrees_with, remaining_uncertainty, optional sources — plus recorded provenance (provider, model, family, tokens_used, latency_ms, confidence_raw) and `calibrated_confidence` for consensus. (2) Pipeline in `BaseAgent.run()`: hardened `_extract_json` (byte-identical) → strict validate (missing/extra keys, wrong types, empty position, non-numeric/non-finite confidence all reject; out-of-range confidence clamps with raw recorded; unknown agent IDs stripped per Fix B) → exactly one retry with the validation error appended → one fallback-family attempt via `router.fallback_for` (agents now carry router/routing/family from AgentManager) → raise `AgentValidationError`, which the manager converts to a 0.1-confidence error output and debate converts to stale carry-forward (Fix D preserved). Transport errors still propagate for the manager's transport retry. (3) Independent solve is prompt-structural: no critique context means no other agents' answers (tested); researcher additionally reads the orchestrator-injected `search_results` attr (previously dead plumbing — the attribute was set but never read). (4) Consumers adapted minimally: debate compression passes the new fields through, consensus reads `calibrated_confidence`, orchestrator converts sources to dicts at the DB/API boundary, mock scripts emit the new shape. (5) `tests/test_agents.py` (26 tests, one per failure type) + the old text-fallback test rewritten to the new raise-after-retry contract.
- Consequences: `AgentOutput` field renames (`reasoning`→`reasoning_summary`, evidence strings→objects) are breaking for any external reader of workspace events — accepted: the contract was the point of the task, and all in-repo consumers were migrated. New-model-shape strictness may cost one retry + one fallback call on quirky models; the retry message carries the exact schema error to minimize this.

## 2026-10-08 — Consensus rework per WORKFLOW §6 (family votes, 4 decisions, adversarial round)

- Context: The consensus score used agent-counted votes (three same-family solvers outvoted a lone critic 3:1), ad-hoc weights/thresholds scattered as class constants, a 3-way continue/finalize/timeout decision that never fired the WORKFLOW 5b adversarial round, and no structured report of the breakdown.
- Decision: (1) Exact §6 formula with weights/thresholds moved into `Settings` (`consensus_*`, env-overridable for benchmark tuning) surfaced as `ConsensusConfig.from_settings()`; engine accepts an injected config. (2) Agreement and contradiction_ratio computed over a family-stance matrix — one vote per family, intra-family edges ignored, position-share fallback when no cross-family edges exist. (3) `evaluate()` returns `ConsensusReport` (score, decision, reason, 5-factor breakdown, open disagreements with families, new_info_rate, raw edge counts, average_confidence) with decisions in table order: FORCE_FINALIZE (forced/no-time/no-quota) → ADVERSARIAL (round-1 ≥0.85, or unanimous-with-no-evidence) → FINALIZE (≥0.85, new info <0.15, contradiction <0.2) → DEBATE. (4) `select_adversarial_critic` (critic outside the consensus position bloc) + `adversarial_round` (assume-wrong challenge via new `CriticAgent.adversarial_challenge`, output replaces critic's, re-score with adversarial disabled); orchestrator runs one strike per execution then falls back to normal debate, with token accounting. (5) Fix D preserved: failed-round outputs excluded from new-info/stability. `tests/test_consensus.py` (23 tests: unanimous/split/converging/thrashing/failed-agent, exact formula math, all four decisions incl. precedence, strike execution + rescore, orchestrator end-to-end strike, report shape, no-position-logging).
- Consequences: `ConsensusResult` renamed to `ConsensusReport` (`reasoning`→`reason`, new fields); orchestrator loop rewritten around the four decisions; wire-format event key stays `reasoning` so the frontend is untouched. Single-family teams can never trigger a strike (no eligible critic) — correct per anti-echo rule 3, they debate normally instead.

## 2026-10-08 — Time controller: Deadline, per-call timeouts, cancel, explicit §2 states

- Context: Wall-clock enforcement was cooperative only (budget polled between phases, no per-call bound, no user cancel). A hung provider call could stall a run indefinitely; cancelling from the API was impossible; execution phases were implicit (no state machine, states never published).
- Decision: (1) New `src/orchestration/time_controller.py`: `Deadline` (injectable clock + `FakeClock`, `remaining()`, `can_start_round()`, `synth_reserve = max(25s, 12%)` reused from capacity, `timeout_for_call()` derived from remaining time, cancel flag), `TaskTracker` (named tasks, bulk cancel + drain, async-CM), and `ExecState`/`StateMachine` validating the exact §2 diagram (CANCELLED/FAILED_PARTIAL reachable from anywhere). (2) Orchestrator: every phase transition validated + published as a `state` event field (existing `status` strings kept for the frontend); advisory CAPACITY_CHECK via quota snapshot; planner/synthesis wrapped in `asyncio.timeout`; per-agent timeouts threaded through manager/debate (TimeoutError → existing fallback outputs, never CancelledError); debate loop gated on `should_synthesize_now()` + round estimates; CancelledError → wiped keys, workspace cleanup, status "cancelled". (3) API: `_run_tasks` registry, `POST /{id}/cancel` (404/403/terminal-idempotent, thread-safe `_cancel_task`), CancelledError persistence, live `state` persistence from progress events. (4) `quota.acquire` hardened so a cancel between semaphore-acquire and lease creation cannot leak the permit (defense-in-depth; leases already release via `async with`).
- Consequences: `ExecutionResult`/`Execution.status` gain "cancelled"; `ExecutionResult.warnings` now also carries advisory capacity notes. Crash path keeps legacy "failed". Bare-TestClient API tests cannot hold a slow background run across requests (per-request portal teardown cancels it) — covered instead by teardown-persistence + injected-task cancel tests; production uvicorn keeps one loop so the endpoint works as designed.

## 2026-10-08 — Progress event system per WORKFLOW §8 (models, log, replay)

- Context: Progress events were ad-hoc dicts (`status_update`, `answer_ready`, …) with no contract, no persistence, and no way for a refreshed browser to catch up — plus no systematic guarantee against keys or chain-of-thought leaking into payloads.
- Decision: (1) New `src/api/events.py`: `ProgressEventType` enum with the 17 canonical dotted names (§8 table + `execution.cancelled` for the §2 CANCELLED state), one strict Pydantic payload model per type (`extra="forbid"`, short human-readable fields only), `ProgressEvent` envelope `{event_type, execution_id, seq, state?, data, timestamp}`, `sanitize_payload` (drops forbidden key names at any depth, masks SecretStr, truncates >2000 chars), `EventRecorder` (validates + sanitizes + assigns dense per-execution seqs; validation failures are dropped with an error log, never crash the run), and DB helpers (`persist_event` idempotent on `(execution_id, seq)`, ordered `fetch_events`, `fetch_latest_seq`, `event_schema_bundle`). (2) New `execution_events` table (seq, type, payload JSON, unique per execution+seq, cascade delete). (3) Orchestrator remapped to §8 emits (incl. `round.finished`, disagreement opened/resolved diffing, `source.found`/`verified`, `quota.warning` on downgrade/token pressure, `timer.tick` heartbeat, confidence labels per §6 bands); lifecycle `state` rides in the envelope so existing state persistence keeps working. (4) API persists every event before broadcast; WS `?after_seq=N` registers-then-replays with a per-connection watermark deduping the live overlap; new `GET /{id}/events?after_seq=&limit=` REST fallback with ownership checks. (5) Frontend handles new names (legacy cases kept), tracks seq with dedup + localStorage, reconnects with backoff passing `after_seq`. (6) `scripts/export_event_schema.py` → committed `frontend/event-schema.json` for TS derivation; envelope also lands in OpenAPI via the REST response model.
- Consequences: Wire format is §8-canonical (breaking change for any external WS consumer — accepted: the contract was the task). Crash path still writes DB status "failed" while emitting `execution.failed_partial` (preserves existing poll loops). `execution.cancelled` has no §8 row; justified by the §2 state machine. Bare-TestClient cannot test live mid-run streaming (per-request portals), so reconnect tests replay completed runs; residual replay/live overlap is deduped, documented, and client-tolerated.

## 2026-10-08 — Final composer: cited-only sources, banded notes, verification

- Context: The final answer was the synthesizer's raw position plus an unattributed footer — citations were unverified ([n] markers could point nowhere), unreferenced sources shipped in the Sources list, and there was no machine-readable record of what the team actually verified.
- Decision: (1) New `src/orchestration/composer.py` — pure functions, no LLM calls: `confidence_label_for_score` (High ≥ 0.85 / Moderate ≥ 0.60 / Low, exactly the §6 wording bands), citation collection from `[n]` text markers (Markdown links excluded) plus numeric evidence source_ids, renumbering to a dense 1..K list with orphan markers neutralized to `[?]` + warnings, `build_uncertainty_note` / `build_alternatives_note` with honest fallbacks so the sections are never empty when required, shared `attribution_footer` (synthesizer now calls it — one definition), and `compose_final_answer` returning a frozen `ComposedAnswer` (Markdown answer, label, notes, cited-only sources, `VerificationSummary`, warnings, score). (2) Synthesizer prompt updated to cite numbered `[n]` sources and write Markdown; JSON contract unchanged (base_agent validation untouched). (3) Orchestrator composes after synthesis (candidate pool = synth sources else team sources, as before), tracks disagreements-resolved from emitted deltas, and wires the composed answer + verification into `ExecutionResult` and the `execution.completed` event (new optional `verification` field on both).
- Consequences: Answers now always end with Confidence line + footer, and conditionally carry uncertainty (<0.85), alternatives (<0.60), and Sources sections. Uncited pool sources are dropped by design (mock e2e answers legitimately have no Sources section). The event `confidence_label` (high/medium/low) is unchanged; the composer label (High/Moderate/Low) is a separate display string for the answer text.

## 2026-10-08 — Citation quality: dedupe, credibility ranks, cross-verification

## 2026-10-08 — Prompt-injection defense for web content (sanitize + delimit + detect)
